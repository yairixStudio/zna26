# CLAUDE.md — ZNA 2026 lineup guide

Working notes for Claude (and other agents) on this codebase. The product
is an unofficial fan guide to **ZNA Gathering 2026** (Goa-trance festival,
Portugal, July 2026). It's a static site deployed via GitHub Pages; no
build step beyond an optional photo-scrape that runs in the GitHub Action.

## Files at a glance

```
index.html        — single-page shell (top bar, mini-player, search overlay)
data.js           — ARTISTS array + ARTIST_EXTRAS + ARTIST_TRANSLATIONS
app.js            — state machine, render functions, gestures, i18n, peek
styles.css        — full styling (mobile-first, with desktop & landscape passes)
photos.json       — id → local image path, generated by build/fetch-photos.mjs
images/artists/   — local artist photos (committed)
images/zna-3d/    — festival-supplied 3D elements
.github/workflows/pages.yml — Action that runs the photo scraper + deploys
build/fetch-photos.mjs       — scraper for znagathering.com photos
```

## Architecture

Vertical reel of full-screen sections:

  1. **Multi-hero** — single section with a horizontal pager of 5 hero panels
     (Main + 4 stages). Swiping horizontally between hero panels updates
     `activeStageFilter` and re-renders the artist list below.
  2. **Artist sections** — one per filtered artist. Each artist section is a
     horizontal pager with a 6-panel **infinite-loop carousel**:
     `[cloneStart][Hero][Info][Tracks][Discography][cloneEnd]`. A debounced
     settle handler instant-jumps from a clone to its real twin (identical
     content) so the loop is visually seamless.

Vertical scroll wraps too — past the last section sends the user back to the
hero (and vice versa for above-hero), via both wheel/keyboard
(`navVertical` modulo) and touch (overscroll-detection on `touchend`).

## Internationalisation

The site supports **English (default), Hebrew, Portuguese**.

- UI strings live in `STRINGS` (in `app.js`), keyed by short id with an
  object of `{ he, en, pt }` values. `t(key, vars)` looks them up; missing
  translations fall back through `currentLang → en → he → key`.
- Per-artist translatable fields (`bio`, `notable`, `country`, `born`) live
  in `ARTIST_TRANSLATIONS` (in `data.js`). At boot, `app.js` merges them
  onto each artist as `a.translations = { he, en, pt }`. `tArtist(a, field)`
  reads the right one.
- `tStage(stageId, "name"|"desc")` returns the stage label / description.
- The user picks a language from a 3-flag row at the **bottom of the stage
  dropdown menu** (top-right corner, `🇬🇧 / 🇮🇱 / 🇵🇹`). `applyLang()` saves
  the choice to `localStorage["zna-lang"]` and re-renders the entire reel.

When you add new UI copy, **always add it to `STRINGS` with all three
languages** — never inline a hard-coded Hebrew string in a render
function. When you add a new artist, populate `ARTIST_TRANSLATIONS[id]`
with `bio`/`notable`/`country`/`born` in EN and PT (HE stays on the
ARTISTS record). Translation runs of bulk content can be delegated to a
sub-agent — there's a working prompt template higher up in this thread.

## Playback model

A single YouTube IFrame Player instance is moved between an inline track
card and the bottom mini-player. State in three vars:
`playerLocation = "none" | "inline" | "mini"`, `inlineHostEl`,
`currentVideoId`. `IntersectionObserver` on the inline frame triggers
`migratePlayerToMini()` the moment the frame leaves the viewport. The
queue auto-advances on `ENDED` and shows a `Next up:` preview.

Mini-player UX: tap **anywhere** on the collapsed bar (chrome, title,
artist, empty area) to expand. Expanded layout uses
`grid-template-areas: "controls" "frame" "info"` so buttons sit ABOVE the
iframe, never overlaying the YouTube player. Click handler fires on both
`click` and `pointerup` for iOS reliability.

## Carousel reset rules

- Section becomes active → `setActiveSection` re-anchors its pager to
  panel index 1 (real Hero) if it lands on a clone, and forces all OTHER
  artist sections to anchor at panel 1 too.
- Section drops below 25% intersection → IntersectionObserver resets that
  section's pager to panel 1 (so coming back lands on Hero, not mid-deck).
- Loop wraps use `pagersBeingWrapped` WeakSet + 250ms hard-fallback so a
  busy main thread can never leave a pager permanently locked.

## Dot tap targets (artist panel indicators)

Two-stage tap to avoid accidental navigation:

1. **Idle**: dots are tiny, no pill chrome, generous transparent padding.
2. **First tap on the strip**: arms it (`.is-armed`) — pill chrome appears,
   dots grow ~3x, **no navigation happens**.
3. **Tap a dot while armed**: navigates to that panel; the 4s TTL resets.
4. **4s without a tap**: relax back to idle.

## Festival schedule + live-status

`FESTIVAL.startsAt`, `FESTIVAL.endsAt`, `FESTIVAL.timezone` and
`ARTIST_SCHEDULE` (in data.js) feed `getScheduleStatus(stage)` and the
hero's compact countdown card. Per-artist set times can be inlined via
`schedule: { start, end }` on an artist record or via `ARTIST_SCHEDULE[id]`.
Until the official schedule lands, badges read **T.B.A.** in the active
language.

## Build-time photo scrape

`build/fetch-photos.mjs` runs in the GitHub Action with full outbound
network access (which Claude's local sandbox does not have). It pulls
`/program/`, `/program/dancefloor/`, the per-stage program pages, and 13
individual artist-announcement posts. It extracts `<img>` tags, CSS
`background-image` URLs, and any `wp-content/uploads/...` URL anywhere in
the HTML, then matches each to an artist via alt-text / title / filename
/ page-title fallback. Output → `photos.json`.

If a future scrape needs to capture more (e.g. ZNA-authored
descriptions), extend that script — don't try to fetch znagathering.com
from this sandbox; it consistently 403s.

## Deployment

Push to `claude/zna-festival-guide-4Uu3t` triggers the workflow at
`.github/workflows/pages.yml`. The job: `npm install` deps if any, run
the photo scraper (continue-on-error), upload everything in the repo
root as the Pages artifact, deploy. Live URL is printed at the end of
the action.

## Things that broke before — don't reintroduce them

- `overscroll-behavior: contain` on `.panel` traps vertical pans inside
  long panels (Info/Tracks). Use `overscroll-behavior-x: contain` only.
- `installSnapClamp` on the per-artist `.pager` mis-reads carousel wraps
  as "user jumped > 1 step" and triggers spurious correction scrolls.
  Native `scroll-snap-stop: always` is enough on that axis.
- `pager.children[0]` is the **cloneStart**, not the artist's Hero. The
  Hero sits at `children[1]`. Anchoring scrollTo / vertical-reset uses
  `children[1]`; only the carousel's own jump logic touches `children[0]`.
- iOS Safari's `click` is unreliable on non-interactive divs. The mini-
  player's click-to-expand listens on both `click` and `pointerup`.
- Heavy `backdrop-filter: blur(28px) saturate(180%)` stacks ran the
  iPhone GPU out of memory; cap at ~14px and avoid stacking.
